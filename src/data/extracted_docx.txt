[3] 1. Platform Independence, JDK, JRE, JVM
[4] What is platform independence?
[5] Java is called platform-independent because Java source code is compiled into bytecode. This bytecode can run on any operating system that has a compatible Java Virtual Machine (JVM). This is commonly described as “Write Once, Run Anywhere.”
[6] How does Java achieve platform independence?
[7] The Java compiler (javac) converts source code (.java) into bytecode (.class). A JVM designed for the target operating system executes that bytecode. The bytecode is portable; the JVM implementation is platform-specific.
[8] Java source (.java) → javac compiler → bytecode (.class) → JVM → machine instructions
[9] JVM, JRE, and JDK
[10] JVM (Java Virtual Machine) executes Java bytecode. JRE (Java Runtime Environment) provides the JVM and runtime libraries needed to run Java applications. JDK (Java Development Kit) includes development tools such as the compiler and the runtime components needed to develop and run Java programs.
[11] What is bytecode?
[12] Bytecode is the intermediate instruction format produced by the Java compiler. It is not native machine code for one particular operating system; the JVM interprets it or compiles it to native instructions at runtime.
[13] 2. Data Types and Character Encoding
[14] What is a data type?
[15] A data type specifies what kind of value a variable can store and which operations can be performed on that value.
[16] Primitive data types
[17] Java has eight primitive data types: byte, short, int, long, float, double, char, and boolean. The first six store numeric values, char stores a UTF-16 code unit, and boolean stores true or false.
[18] Reference types
[19] Reference types include classes, arrays, interfaces, enums, and types such as String. A reference variable holds a reference to an object, or null; it does not directly store the complete object.
[20] ASCII vs Unicode
[21] ASCII is a character-encoding standard with 128 basic characters, including English letters, digits, and control characters. Unicode is a universal character standard intended to represent characters from writing systems around the world. Some Unicode characters require a pair of Java char values.
[22] Example: ASCII 'A' has value 65.
[23] 3. Type Casting
[24] What is type casting?
[25] Type casting is converting a value from one data type to another.
[26] Widening (implicit) casting
[27] Widening converts a value to a compatible type with a wider range, such as int to long. It is usually automatic, though some numeric conversions (such as long to float) can still lose precision.
[28] int a = 10;\ndouble b = a;
[29] Narrowing (explicit) casting
[30] Narrowing converts a value to a type with a smaller range or precision. It generally requires an explicit cast and may lose information.
[31] double x = 10.8;\nint y = (int) x; // y becomes 10
[32] 4. Operators
[33] What is an operator?
[34] An operator is a symbol that performs an operation on one or more values or variables. The values it acts on are called operands.
[35] int a = 5, b = 10;\nSystem.out.println(a + b); // + is an operator; a and b are operands
[36] Types of operators
[37] Arithmetic: +, -, *, /, %. Relational: <, >, <=, >=, ==, !=. Logical: &&, ||, !. Assignment: =, +=, -=, *=, etc. Unary: ++, --, +, -, !, ~. Conditional/ternary: condition ? value1 : value2. Bitwise: &, |, ^, ~. Shift: <<, >>, >>>.
[38] Pre/post increment and decrement
[39] Pre-increment (++x) increases x first and then produces the new value. Post-increment (x++) produces the current value first and then increases x. Pre-decrement (--x) decreases first; post-decrement (x--) uses the current value first and decreases afterward.
[40] int a = 5; System.out.println(++a); // 6\nint b = 5; System.out.println(b++); // prints 5; b becomes 6
[41] 5. Variables
[42] What is a variable?
[43] A variable is a named storage location used by a program to hold a value. The value of a variable may change while the program runs.
[44] Local variable
[45] A local variable is declared inside a method, constructor, or block. Its scope is limited to that method or block. Java does not automatically assign a default value to local variables; they must be assigned before use.
[46] Instance variable
[47] An instance variable is declared in a class but outside methods, constructors, and blocks, without static. Each object has its own copy. Instance fields receive default values when an object is created.
[48] Static variable
[49] A static variable is declared with static. It belongs to the class and is shared by all instances of that class. It receives a default value if no explicit value is assigned.
[50] Local vs instance variable
[51] A local variable belongs to a method or block, is usable only within its scope, and has no automatic default value. An instance variable belongs to an object, is declared at class level, and receives a default value. Instance variables are part of the object; local variables are associated with method execution. JVM implementation details can vary.
[52] 6. Methods and Pass-by-Value
[53] What is a method?
[54] A method is a named block of code that performs a specific task. It can accept parameters and may return a value.
[55] Four common method forms
[56] 1) No parameters, no return value. 2) Parameters, no return value. 3) No parameters, returns a value. 4) Parameters and returns a value.
[57] int add(int a, int b) { return a + b; }
[58] Pass-by-value in Java
[59] Java is always pass-by-value. A method receives a copy of the argument value. For primitives, the primitive value is copied. For objects, the reference value is copied, so a method can change the object's state but cannot replace the caller's reference variable.
[60] Method overloading
[61] Method overloading means defining multiple methods with the same name in the same class but different parameter lists (number, types, or order). Return type alone cannot distinguish overloaded methods.
[62] void show(int x) {}\nvoid show(String x) {}
[63] 7. JVM Memory and Garbage Collection
[64] High-level JVM memory areas
[65] Each thread has its own JVM stack for method frames and local variables. The heap stores objects and arrays. The JVM also maintains class metadata and runtime data. Avoid assuming every static field always resides in one fixed physical memory segment; implementation details vary.
[66] What is garbage collection?
[67] Garbage collection is the JVM's automatic process of reclaiming heap memory used by objects that are no longer reachable. Developers cannot guarantee exactly when it runs; System.gc() is only a request.
[68] What happens when a method finishes?
[69] When a method completes, its stack frame is removed from that thread's stack. An object on the heap is not removed merely because a method finishes; it can be reclaimed when it becomes unreachable and the garbage collector later processes it.
[70] 8. OOP, Classes, Objects, Arrays
[71] What is OOP?
[72] Object-oriented programming (OOP) organizes software around classes and objects. It helps model real-world entities and supports modularity, reuse, and maintainability.
[73] What is a class?
[74] A class is a blueprint or template that defines the fields (state) and methods (behavior) that its objects can have.
[75] What is an object?
[76] An object is a runtime instance of a class. It has state (field values), behavior (methods), and identity. The new keyword commonly creates class objects.
[77] class Employee { int id; String name; }\nEmployee e = new Employee();
[78] What is an array?
[79] An array is an object that stores a fixed number of elements of one declared component type. Elements are accessed by zero-based indexes, from 0 to length - 1. An array's length cannot change after creation.
[80] int[] arr = {10, 20, 30, 40};\nSystem.out.println(arr[0]); // 10
[81] Multidimensional arrays
[82] A two-dimensional Java array is an array whose elements refer to other arrays. Inner arrays can have different lengths, so Java supports jagged arrays.
[83] 9. Strings
[84] What is String?
[85] String is a class in java.lang used to represent a sequence of characters. String objects are immutable: once created, their contents cannot be changed. Operations that appear to modify a String return a new String.
[86] Why is String immutable?
[87] Immutability supports safe sharing, the String constant pool, reliable hash-based keys, and security-sensitive uses. It also makes String objects naturally safe to share between threads.
[88] String constant pool
[89] The string pool is a JVM-managed pool of canonical String instances. String literals and explicitly interned strings can share pooled instances. A String created with new normally creates a distinct String object even if an equal value is pooled.
[90] Common String methods
[91] equals() compares content; == compares primitive values or reference identity; length() returns UTF-16 code-unit length; charAt(i) returns a char; substring() extracts a portion; indexOf()/lastIndexOf() search; startsWith()/endsWith() check prefixes/suffixes; trim()/strip() remove surrounding whitespace under different rules; toUpperCase()/toLowerCase() change case; replace() replaces text; split() divides text using a regular expression; isEmpty() checks length zero; valueOf() converts values to strings; compareTo() compares lexicographically.
[92] String vs StringBuilder vs StringBuffer
[93] String is immutable. StringBuilder is mutable and usually preferred for repeated changes in a single thread because it is not synchronized. StringBuffer is mutable and its methods are synchronized.
[94] StringBuilder sb = new StringBuilder("Java");\nsb.append("Script");\nSystem.out.println(sb); // JavaScript\nsb.length();   // current character count\nsb.capacity(); // current storage capacity
[95] StringBuilder length and capacity
[96] length() is the number of characters currently stored. capacity() is the storage available before expansion is needed. An empty StringBuilder has a default capacity of 16; constructing it with a String gives an initial capacity equal to the string length plus 16.
[97] split() vs StringTokenizer
[98] String.split() divides text using a regular expression and returns a String array. StringTokenizer is a legacy utility class that separates text using delimiter characters; for modern code, split() or a clearer parser is often preferred.
[99] 10. Encapsulation, Getters, Setters, this
[100] What is encapsulation?
[101] Encapsulation bundles data and the methods that operate on it within a class and restricts direct access to internal state. It is commonly implemented with private fields and public methods that control access.
[102] Getter and setter
[103] A getter returns or reads a field's value. A setter assigns or updates a field's value and can validate the value before changing the field.
[104] class BankAccount {\n  private double balance;\n  public double getBalance() { return balance; }\n  public void setBalance(double balance) {\n    if (balance >= 0) this.balance = balance;\n  }\n}
[105] Advantages of encapsulation
[106] Encapsulation supports data hiding, controlled access, validation, lower coupling, and easier maintenance.
[107] Variable shadowing
[108] Shadowing occurs when a variable in a more local scope has the same name as a variable in an outer scope. this.field refers to the current object's field when a parameter or local variable has the same name.
[109] Employee(int id) { this.id = id; }
[110] What is this?
[111] this refers to the current object. It can distinguish fields from parameters and call another constructor in the same class using this(...). A this(...) constructor call must be the first statement in that constructor.
[112] 11. static Keyword
[113] What does static mean?
[114] static marks a member as belonging to the class rather than to each object. Static fields are shared by instances, and static methods can be called using the class name.
[115] Static method limitation
[116] A static method has no current-object this reference and cannot directly access instance fields or instance methods without an object reference. It can directly access static members.
[117] Static block
[118] A static initialization block runs when the class is initialized, before the class is used to create its first instance or invoke its static method, subject to Java class-initialization rules.
[119] When should a variable be static?
[120] Use a static variable when the value represents shared class-level state rather than separate state for each object, such as a shared constant or an instance counter.
[121] 12. Constructors and Constructor Chaining
[122] What is a constructor?
[123] A constructor initializes a new object. It has the same name as its class and has no return type, not even void. It is invoked when an object is created.
[124] Default constructor
[125] If a class declares no constructor, the compiler provides a no-argument default constructor. If you declare any constructor, the compiler does not automatically add that default constructor.
[126] No-argument and parameterized constructors
[127] A no-argument constructor takes no parameters. A parameterized constructor accepts parameters so fields can be initialized with supplied values.
[128] Copy constructor
[129] Java does not automatically provide a special copy-constructor feature. A copy constructor is programmer-defined and accepts an object of the same class, copying selected values into a new object.
[130] Student(Student other) { this.name = other.name; this.age = other.age; }
[131] Constructor overloading
[132] Constructor overloading means defining multiple constructors in the same class with different parameter lists.
[133] Constructor chaining
[134] Constructor chaining is when one constructor calls another to reuse initialization logic. Use this(...) for another constructor in the same class, or super(...) for a parent constructor. The call must be the first statement.
[135] Cyclic constructor chaining
[136] Cyclic constructor chaining occurs when constructors call one another in a cycle. Java rejects such a cycle at compile time.
[137] 13. Inheritance
[138] What is inheritance?
[139] Inheritance allows a subclass to acquire accessible fields and methods from a superclass. A class uses extends to inherit from one direct superclass. Inheritance supports code reuse and method overriding.
[140] Single inheritance
[141] One child class extends one parent class.
[142] Multilevel inheritance
[143] A class extends a class that itself extends another class, forming a chain.
[144] Hierarchical inheritance
[145] Two or more child classes extend the same parent class.
[146] Multiple inheritance
[147] Java classes cannot extend multiple classes, but a class can implement multiple interfaces. This avoids ambiguity from inheriting implementation from multiple parent classes.
[148] Hybrid inheritance
[149] Hybrid inheritance combines two or more inheritance patterns. Java designs can combine class inheritance and interfaces.
[150] is-a relationship
[151] An is-a relationship means one type is a specialized form of another type. For example, Dog is an Animal when Dog extends Animal.
[152] Inherited, overridden, specialized behavior
[153] Inherited behavior comes from a parent without changing its implementation. Overridden behavior is a child implementation of an inherited instance method. Specialized behavior is new behavior declared only in the child class. These are descriptive terms, not Java keywords.
[154] 14. super, final, Access Modifiers
[155] What is super?
[156] super refers to the immediate superclass from a subclass. It can access superclass members hidden or overridden by the subclass and call a superclass constructor with super(...).
[157] What is final?
[158] A final variable can be assigned only once. A final method cannot be overridden. A final class cannot be subclassed. A final reference cannot be reassigned, but the referenced object is not automatically immutable.
[159] Access modifiers
[160] public: broadest member access. protected: same package and subclass access under Java's rules. Package-private (no modifier): same package only. private: restricted to the declaring class and permitted enclosing scope.
[161] Access visibility summary
[162] For class members, public is broadest; protected includes same-package and subclass access; package-private is same-package only; private is most restricted. Top-level classes can be public or package-private, not protected or private.
[163] 15. Overriding, Covariant Return, Polymorphism
[164] Method overriding
[165] A subclass overrides an inherited instance method by providing a compatible implementation. The return type must be the same or covariant; access cannot be more restrictive; checked exceptions cannot be broader than allowed. Use @Override to catch mistakes.
[166] class Animal { void sound() { System.out.println("Animal"); } }\nclass Dog extends Animal {\n  @Override void sound() { System.out.println("Dog"); }\n}
[167] Covariant return type
[168] A covariant return type allows an overriding method to return a subtype of the return type declared by the parent method.
[169] What is polymorphism?
[170] Polymorphism means one parent-type reference or common interface can represent objects of different concrete classes. With runtime polymorphism, an overridden instance method is selected according to the actual object at runtime.
[171] Compile-time vs runtime polymorphism
[172] Compile-time polymorphism commonly refers to overloading, where the compiler chooses a method based on its parameter list. Runtime polymorphism refers to overriding, where the actual object's class determines which overridden instance method runs.
[173] Overloading vs overriding
[174] Overloading: same name, different parameter list; inheritance is not required; resolved at compile time. Overriding: subclass provides a compatible implementation of an inherited instance method; inheritance is required; dispatch is determined at runtime.
[175] Can static methods be overridden?
[176] Static methods are hidden, not overridden, because they belong to the class rather than an object. Selection depends on the class/reference type, not runtime overriding dispatch.
[177] Upcasting
[178] Upcasting assigns a subclass object to a superclass reference. It is implicit and safe, but only members visible through the declared reference type can be called directly.
[179] Animal a = new Dog();
[180] Downcasting
[181] Downcasting converts a superclass reference back to a subclass reference. It needs an explicit cast and is safe only if the object really is an instance of that subclass; otherwise, ClassCastException may occur.
[182] if (a instanceof Dog) { Dog d = (Dog) a; }
[183] Method hiding
[184] Method hiding occurs when a subclass declares a static method with the same signature as a superclass static method. Selection depends on the class/reference type.
[185] 16. Abstraction and Interfaces
[186] What is abstraction?
[187] Abstraction exposes essential operations while hiding unnecessary implementation details. In Java, it is commonly achieved with interfaces and abstract classes.
[188] Abstract class
[189] An abstract class is declared with abstract and cannot be instantiated directly. It can contain abstract methods, concrete methods, fields, constructors, and static methods. A concrete subclass must implement inherited abstract methods unless it is also abstract.
[190] Abstract method
[191] An abstract method is declared without a method body and ends with a semicolon. A concrete subclass must implement it unless it inherits an implementation.
[192] Concrete method
[193] A concrete method has an implementation body.
[194] Pure and partial abstraction
[195] These are informal teaching terms, not Java language categories. Interfaces are often described as providing strong abstraction, while abstract classes can combine abstract and concrete behavior. Modern interfaces can also contain default, static, and private methods.
[196] What is an interface?
[197] An interface defines a contract that implementing classes agree to follow. A class uses implements to implement an interface. Interfaces support abstraction, loose coupling, and polymorphism.
[198] Interface rules
[199] A class can implement multiple interfaces. An interface can extend one or more interfaces. A class can extend one class and implement multiple interfaces. Interface fields are implicitly public, static, and final. Abstract interface methods are implicitly public; interfaces may also have default, static, and private methods with bodies.
[200] Can we create an interface object?
[201] An interface cannot be instantiated directly. An interface reference can point to an object of an implementing class, anonymous class, or suitable lambda expression.
[202] Marker interface
[203] A marker interface has no declared methods and marks a class as having a particular property or signals behavior to a framework/runtime. Serializable is a common example.
[204] Abstract class vs interface
[205] An abstract class is useful when related classes share state or implementation; a class can extend only one class. An interface defines a contract that unrelated classes can implement, and a class can implement multiple interfaces.
[206] 17. Has-a, Aggregation, Composition
[207] Has-a relationship
[208] A has-a relationship exists when one class contains or uses an object of another class. For example, a Car has an Engine.
[209] Aggregation
[210] Aggregation is a weak has-a relationship: the contained object can exist independently of the container.
[211] Composition
[212] Composition is a stronger has-a relationship in which the containing object owns the contained part as part of its lifecycle or responsibility. Exact lifecycle behavior depends on the design.
[213] Aggregation vs composition
[214] The distinction is ownership and lifecycle dependency: composition expresses stronger ownership, while aggregation expresses a looser association. These are design concepts, not Java keywords.
[215] 18. Exception Handling
[216] What is an exception?
[217] An exception is an object representing an abnormal condition during execution that interrupts the normal flow unless it is handled.
[218] Exception hierarchy
[219] Throwable is the root class for objects that can be thrown. Its main branches are Error and Exception. RuntimeException is a subclass of Exception.
[220] Error vs exception
[221] An Error generally represents a serious problem, such as OutOfMemoryError or StackOverflowError. An Exception represents a condition an application may handle, such as IOException or ArithmeticException. A syntax error is normally a compile-time error, not a java.lang.Error object.
[222] Checked vs unchecked exceptions
[223] Checked exceptions must be caught or declared; IOException is an example. Unchecked exceptions are RuntimeException subclasses and need not be caught or declared; NullPointerException and ArithmeticException are examples. Error subclasses are also unchecked.
[224] try, catch, finally
[225] A try block contains code that may throw an exception. A catch block handles a matching exception. A finally block normally runs after try/catch and is commonly used for cleanup, though abrupt JVM termination can prevent it from running.
[226] try { int result = 10 / 0; }\ncatch (ArithmeticException e) { System.out.println(e.getMessage()); }\nfinally { System.out.println("Cleanup"); }
[227] Multiple catch blocks
[228] A try block can have multiple catch blocks for different exception types. More specific types must appear before more general types.
[229] getMessage() and printStackTrace()
[230] getMessage() returns an exception's detail message, which may be null. printStackTrace() prints the exception and its stack trace.
[231] Exception propagation
[232] Exception propagation means an exception moves up the call stack when the current method does not handle it. It continues until a matching handler is found or the thread's uncaught-exception handler handles it.
[233] throw vs throws
[234] throw is a statement that explicitly throws one exception object. throws appears in a method or constructor declaration to declare exception types the caller may need to handle.
[235] throw new IllegalArgumentException("Invalid age");\nvoid readFile() throws IOException { /* ... */ }
[236] Exception ducking
[237] Exception ducking is an informal term for declaring an exception with throws rather than handling it in the current method, leaving the caller responsible for handling or declaring it further.
[238] Default exception handler
[239] If an exception reaches the top of a thread's call stack without being caught, the uncaught-exception handler is invoked. The default handler typically prints the exception and stack trace.
[240] Custom exception
[241] A custom exception is a programmer-defined exception for an application-specific error. Extend Exception for a checked exception or RuntimeException for an unchecked exception.
[242] class InvalidAgeException extends Exception {\n  InvalidAgeException(String message) { super(message); }\n}
[243] 19. Functional Interfaces, Inner Classes, Lambda
[244] Functional interface
[245] A functional interface has exactly one abstract method, ignoring methods matching public methods of Object. It may also contain default, static, and private methods. @FunctionalInterface asks the compiler to verify the rule.
[246] Regular class
[247] A regular class is a standard class declared at top level or as a member. It defines fields, constructors, and methods and can be instantiated if it is not abstract.
[248] Inner class
[249] A non-static nested class declared inside another class is an inner class. Its instance is associated with an instance of the enclosing class and it can access the enclosing object's members.
[250] Outer outer = new Outer();\nOuter.Inner inner = outer.new Inner();
[251] Static nested class
[252] A static nested class does not require an instance of the outer class to be created.
[253] Local class
[254] A local class is declared inside a method or block and is visible only within that scope.
[255] Anonymous class
[256] An anonymous class has no declared name and is used to instantiate a class or implement an interface while providing behavior at the point of use.
[257] Lambda expression
[258] A lambda expression is a concise way to provide an implementation of a functional interface. The compiler infers the target functional-interface type from context.
[259] Runnable task = () -> System.out.println("Hello");\ntask.run();
[260] Why use lambdas?
[261] Lambdas reduce boilerplate when passing behavior as data, especially with functional interfaces, collections, streams, and event-handling APIs.
[262] 20. Corrections You Must Remember
[263] Java is always pass-by-value. For object arguments, a copy of the reference is passed; Java is not pass-by-reference.
[264] Local variables have no automatic default value. Instance and static fields do receive default values.
[265] A class can extend only one class, but it can implement multiple interfaces. An interface can extend multiple interfaces.
[266] Interfaces can contain default and static methods, and modern interfaces can contain private helper methods. It is incorrect to say every interface method must be abstract.
[267] Static methods are hidden, not overridden. Runtime polymorphism applies to overridden instance methods.
[268] The compiler supplies a default constructor only if the class declares no constructor.
[269] A constructor has no return type. Writing void makes it a method, not a constructor.
[270] String is immutable; StringBuilder is mutable and unsynchronized; StringBuffer is mutable and synchronized.
[271] An array has a fixed length and indexes begin at 0.
[272] A syntax/compile-time error is not the same as a java.lang.Error object.
[273] System.gc() does not guarantee immediate garbage collection.
[274] An object's heap memory is not reclaimed just because a method finishes. The object must become unreachable, and garbage collection occurs later.
[275] Use equals() to compare String content. Use == for primitive equality or reference identity.
